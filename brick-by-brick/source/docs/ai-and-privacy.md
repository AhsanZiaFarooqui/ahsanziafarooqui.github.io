# Live AI role and privacy boundary

The Bayesian engine is deterministic application code and works without a language model. The optional live AI role is educational wording assistance: respond to a short explanation of the child's thinking, reword a targeted lesson, choose one supported visual example and suggest a whitelisted guided follow-up. It does not decide correctness, manufacture likelihoods, diagnose the child or change stored probabilities.

For the free shared website, `server/cloudflare.ts` uses a Cloudflare Workers AI binding named `AI`, the model `@cf/meta/llama-3.3-70b-instruct-fp8-fast`, constrained JSON output and a 14-second timeout. It accepts the production GitHub Pages origin and local development origins. Its modest per-isolate limit is eight requests per minute per IP; this is not distributed abuse protection. Cloudflare may process network metadata as part of hosting. It stores no application learner database. Quota failure uses the built-in explanation. No provider key or paid API is used by this deployment. Live success remains unverified until deployment and a real response. See [setup](../deploy/CLOUDFLARE-SETUP.md).

The optional original local adapter uses the OpenAI Responses API with strict JSON Schema through `text.format`, `store:false`, a 10-second timeout, and no tools. This implementation follows the [official Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs). A successful mocked provider request was tested. **No credential was present; no live provider response was verified.** The example model is configurable; availability is account-dependent.

The browser calls `/api/explain` with only conceptId, optional current itemId and response outcome, the relevant skill's evidence status, and optional short reasoning text (max 300 characters). The server reconstructs the current item from its own bank. No session identifier, names field, full history, journal, or raw posterior array is sent to the provider. Optional reasoning is not stored by this app. Obvious email addresses, URLs and phone-like strings are removed; this is not a guarantee of complete anonymisation. The UI asks learners to leave out names and personal details. Provider handling remains subject to the account's applicable data policies; `store:false` is not a promise of zero provider retention.

Output fields are conceptId, explanation, visualAction, visualParameters, stepCaptions and followUpItemId. Allowed actions are clock-example and fraction-example. The example must belong to that concept; every integer parameter must exactly match the trusted catalogue. Follow-ups must belong to the same topic/target skill and be guided items. Unknown fields, HTML-like text, links, mismatched mathematical parameters, unsupported actions and invalid shapes fail validation. Labels and geometry are rendered from the canonical example, not from generated quantities. No model-generated code/HTML is evaluated.

The model is instructed to treat learner text as untrusted data. Obvious instruction-injection and unrelated text use the checked built-in explanation without calling the provider. These filters are deliberately conservative and **are not a proof against every injection or every harmful/inaccurate prose response**. Schema correctness and validated visual parameters do not mathematically verify arbitrary sentences. Keep supervised use, review live outputs and extend content checks before wider deployment.

Missing keys, invalid responses, refusal, malformed JSON, provider errors, timeout, endpoint/network failure and rate limit errors all preserve progress and return (or locally select) the built-in explanation. A script is never labelled live AI. The original local endpoint rate-limits to 15 requests per minute per local source address and rejects cross-origin calls. It binds locally and keeps no server-side learner database or request-body logs. A public deployment would need a separate security, safeguarding and data-governance review.

Local data resides only under `brick-by-brick:v1` in browser localStorage. This is anonymous by design, not encrypted. A shared-device user can access Grown-ups. Exported files are outside the app's deletion scope. The delete button removes only this app's key; reset removes just the selected session. Journal exports are separate from evidence exports. No microphone, account, analytics, trackers or external fonts are required.
